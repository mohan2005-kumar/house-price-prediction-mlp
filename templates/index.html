Why Entity Embeddings over One-Hot Encoding?

One-hot encoding treats all categories as equidistant and orthogonal, exploding matrix sparsity. Entity Embeddings project discrete entities into low-dimensional learned manifold where semantically related neighborhoods (e.g., Lakefront and Silicon Corridor) naturally cluster in Euclidean distance.

Q: How did you design the Embedded MLP architecture?

Answer: I separated categorical features (neighborhood, property type, furnishing) and continuous features. For categoricals, I constructed PyTorch embedding layers with dimensions chosen using heuristic formula $\min(16, \lceil \sqrt{C} \times 2 \rceil)$. The embeddings are concatenated with standardized continuous variables and passed through a 4-layer MLP with Batch Normalization, LeakyReLU, and Dropout to combat overfitting.

Q: How did you clean the raw housing data with Pandas?

Answer: I handled missing numerical values using median imputation, imputed categorical missing values with the mode, engineered features including age at sale and bed-to-bath ratios, parsed unstructured amenities lists into binary flags, and standardized numerical scales.

Q: What evaluation metrics did you achieve?

Answer: On a holdout 750-sample test set (15%), the model achieved an R² score of 0.9658 (96.6%), a Mean Absolute Error (MAE) of ₹57,482, and an RMSE of ₹78,902 with a MAPE under 7.5%.
